## Описание проекта

**FinTech Dashboard** — это full-stack SPA для персонального финансового учёта. [КРАТКОЕ_ОПИСАНИЕ_ПРОБЛЕМЫ].

Приложение решает следующие сценарии:

- **Учёт расходов и доходов** — добавление, редактирование, удаление транзакций в реальном времени.
- **Визуальная аналитика** — круговая диаграмма категорий, линейный график динамики баланса, KPI-панель.
- **AI-советы** — на основе ваших данных модель Ollama даёт персонализированные рекомендации.
- **Распознавание чеков** — загрузите фото чека — AI извлечёт сумму, дату, категорию и магазин.
- **Бюджетирование** — установите лимиты на категории и следите за перерасходом.
- **Подушка безопасности** — контроль долгов и расчёт нормы финансовой подушки (3–6 месячных расходов).

Архитектура построена на **Feature-Sliced Design** и рассчитана на масштабирование: обогащение данными из банковских API, добавление командных бюджетов, мультивалютность.

## Основные возможности

- [x] **Баланс и сводка** — текущий остаток, доходы и расходы с автоматическим пересчётом при фильтрации
- [x] **Таблица транзакций** — пагинация, редактирование, удаление с оптимистичными обновлениями (React Query)
- [x] **Круговая диаграмма** — структура расходов по категориям (Recharts)
- [x] **Динамика баланса** — линейный график накопленного остатка (running balance)
- [x] **Структура расходов** — группировка по мета-категориям (Жизнь, Комфорт, Обязательные платежи)
- [x] **AI-ассистент** — чат с Ollama (модель `qwen3.5:0.8b`)
- [x] **AI-инсайты** — автоматическая генерация финансового совета на основе данных
- [x] **Распознавание чеков** — загрузка фото через `POST /api/vision` (модель `qwen3-vl:2b`)
- [x] **Фильтры** — поиск, дата, категория, тип транзакции + сброс
- [x] **Бюджетирование** — лимиты на категории с прогресс-баром
- [x] **Финансовая цель** — трекер накоплений с прогрессом
- [x] **Долги и подушка** — учёт долгов, расчёт нормы подушки безопасности
- [x] **Cash Flow Monitor** — мгновенная картина: карта, копилка, кредитка
- [x] **Экспорт CSV** — выгрузка всех транзакций с BOM (Excel-ready)
- [x] **Тёмная тема** — next-themes, системное автоопределение
- [x] **Адаптивная вёрстка** — десктоп, планшет, мобайл (Tailwind CSS)
- [x] **PWA (Progressive Web App)** — установка на домашний экран, офлайн-доступ, service worker
- [x] **KPI-панель** — 6 метрик: общий баланс, доходы/расходы за месяц, средний чек, макс. трата
- [ ] Интеграция с банковскими API (планируется)
- [ ] Мультивалютность (планируется)

## Быстрая установка и настройка

### 1. Клонирование репозитория

```bash
git clone https://github.com/lina-whm/fintech-dashboard.git
cd fintech-dashboard
```

### 2. Установка зависимостей

```bash
npm install
```

### 3. Переменные окружения

Создайте файл `.env.local` в корне проекта:

```env
# Ollama (по умолчанию http://localhost:11434)
# Для доступа с других устройств в локальной сети:
#   Windows: set OLLAMA_HOST=0.0.0.0
#   затем укажите IP вашего ПК: http://192.168.x.x:11434
OLLAMA_API_URL=http://localhost:11434
```

Файл `.env.local` не индексируется git — все секреты храните только в нём.

### 4. Установка Ollama (опционально, для AI-функций)

AI-чат, инсайты и распознавание чеков используют локальные модели через [Ollama](https://ollama.com/).

```bash
# Установите Ollama: https://ollama.com/download

# Загрузите необходимые модели:
ollama pull qwen3.5:0.8b         # для чата и инсайтов
ollama pull qwen3-vl:2b          # для распознавания чеков

# Проверьте, что Ollama запущен:
ollama serve
```

> **ОС Windows:** Ollama запускается как служба автоматически. Если API недоступен, запустите `ollama serve` вручную.

### Деплой на Vercel

Приложение готово к деплою на [Vercel](https://vercel.com) — платформе от создателей Next.js.

**Способ 1 — Vercel CLI:**

```bash
npm i -g vercel
vercel
```

**Способ 2 — GitHub + Vercel (рекомендуется):**

1. Запушьте репозиторий на GitHub.
2. Перейдите на [vercel.com/new](https://vercel.com/new).
3. Импортируйте репозиторий `lina-whm/fintech-dashboard`.
4. Vercel автоматически определит Next.js и применит настройки.
5. Добавьте переменную окружения `OLLAMA_API_URL` (если используете AI-функции на своём сервере).

> ⚠️ AI-функции (чат, инсайты, распознавание чеков) требуют запущенного Ollama. На Vercel они будут возвращать заглушки/ошибки без отдельного AI-сервера. Основной функционал (учёт, аналитика, бюджеты) работает полностью автономно.

## Примеры использования

### Добавление транзакции

1. На панели **«Добавить транзакцию»** заполните поля:
   - **Название** — например, `Кофе в Starbucks`
   - **Сумма** — `450`
   - **Категория** — `Развлечения`
   - **Тип** — `Расход`
   - **Дата** — оставьте сегодняшнюю
2. Нажмите **«Добавить»**.
3. Транзакция мгновенно появится в таблице (optimistic update) и пересчитаются все метрики.

### Вопрос к AI-ассистенту

1. На панели **«AI-ассистент»** введите, например: _«На чём я могу сэкономить в этом месяце?»_
2. Нажмите Enter или кнопку **«Отправить»**.
3. Ответ придёт от локальной модели Ollama.

### Загрузка чека

> Требуется запущенный Ollama с моделью `qwen3-vl:2b`.

1. В панели **«Добавить транзакцию»** нажмите **«Загрузить чек»**.
2. Выберите фото чека (JPG/PNG).
3. Поля формы заполнятся автоматически: сумма, магазин, дата, категория.
4. Проверьте данные и нажмите **«Добавить»**.

### Экспорт в CSV

Нажмите кнопку **«CSV»** в хедере — файл `transactions_YYYY-MM-DD.csv` будет скачан. Файл содержит BOM (`\uFEFF`) для корректного отображения кириллицы в Excel.

## API документация

Базовый URL: `http://localhost:3000`

### `GET /api/transactions`

Возвращает массив всех транзакций.

**Пример ответа:**

```json
[
  {
    "id": "tx-001",
    "title": "Кофе",
    "amount": 450,
    "category": "Развлечения",
    "type": "Расход",
    "date": "2026-04-24"
  }
]
```

### `POST /api/transactions`

Создаёт новую транзакцию.

**Пример запроса:**

```json
{
  "title": "Зарплата",
  "amount": 150000,
  "category": "Зарплата",
  "type": "Доход",
  "date": "2026-04-01"
}
```

**Пример ответа (201):**

```json
{
  "id": "tx-042",
  "title": "Зарплата",
  "amount": 150000,
  "category": "Зарплата",
  "type": "Доход",
  "date": "2026-04-01"
}
```

**Ошибка (400):**

```json
{
  "message": "Название должно содержать минимум 2 символа"
}
```

### `PATCH /api/transactions/:id`

Частичное обновление транзакции.

**Пример запроса:**

```json
{
  "amount": 500
}
```

**Пример ответа (200):**

```json
{
  "id": "tx-001",
  "title": "Кофе",
  "amount": 500,
  "category": "Развлечения",
  "type": "Расход",
  "date": "2026-04-24"
}
```

### `DELETE /api/transactions/:id`

Удаляет транзакцию. Возвращает `204 No Content`.

### `POST /api/transactions/reset`

Сбрасывает store к начальным данным. Возвращает `{ "success": true }`.

### `POST /api/chat`

Отправляет сообщение AI-ассистенту.

**Пример запроса:**

```json
{
  "message": "На чём мне сэкономить?"
}
```

**Пример ответа:**

```json
{
  "reply": "Попробуйте сократить расходы на такси — замените 2 поездки в неделю на метро. Экономия: до 3000 руб./мес."
}
```

### `POST /api/insights`

Генерирует финансовый инсайт на основе транзакций.

**Пример запроса:**

```json
{
  "transactions": [ ... ],
  "summary": {
    "income": 150000,
    "expenses": 80000
  }
}
```

**Пример ответа:**

```json
{
  "insight": "Ваши расходы на еду выше обычного. Попробуйте планировать меню на неделю."
}
```

### `POST /api/vision`

Распознаёт чек по изображению. Принимает `multipart/form-data`.

**Пример (JavaScript fetch):**

```javascript
const formData = new FormData();
formData.append('image', fileInput.files[0]);

const res = await fetch('/api/vision', { method: 'POST', body: formData });
const data = await res.json();
// data: { title, amount, date, category }
```

**Пример ответа:**

```json
{
  "title": "Пятёрочка",
  "amount": 1245.50,
  "date": "2026-04-24",
  "category": "Еда"
}
```

## Известные проблемы и Roadmap

### Известные проблемы

- **ESLint плагин next/core-web-vitals** не загружается — требуется обновление `eslint-config-next`. Не влияет на сборку.
- **AI-функции** требуют локально запущенного Ollama. При отсутствии Ollama API возвращает 500 с описанием ошибки.
- **Пагинация таблицы** сбрасывается при изменении фильтров (не запоминает текущую страницу).
- **Монитор денежных потоков** использует статические демо-данные (15000 / 75000 / 0) — пока нет UI для их изменения.

### Roadmap

- [ ] **MVP 1.1:** Интеграция с банковскими API (банк откроет счета через OpenAPI)
- [ ] **MVP 1.2:** Мультивалютность и конвертация
- [ ] **MVP 1.3:** Регулярные (recurring) транзакции
- [ ] **MVP 1.4:** Уведомления о превышении бюджета
- [ ] **MVP 1.5:** Страница истории с расширенными отчётами (месяц/квартал/год)

## Вклад в проект

### Code style

- TypeScript strict mode — все новые файлы должны быть `.ts` / `.tsx`.
- ESLint + Next.js конфигурация — прогоняйте `npm run lint` перед коммитом.
- Feature-Sliced Design — новые фичи кладите в `features/`, виджеты в `widgets/`.

### Оформление Pull Request

1. Создайте ветку от `main`: `git checkout -b feature/ваша-фича`
2. Внесите изменения и закоммитьте по [Conventional Commits](https://www.conventionalcommits.org/):

```
feat: add recurring transactions support
       ^- тип: feat / fix / chore / docs / test / refactor / style

       ^- краткое описание в повелительном наклонении
```

3. Убедитесь, что тесты проходят:

```bash
npm run test && npm run lint && npm run build
```

4. Откройте PR на GitHub. В описании укажите:
   - Что сделано
   - Скриншоты (если UI-изменения)
   - Ссылка на связанный issue (если есть)

### Требования к коммитам

| Тип | Назначение |
|-----|------------|
| `feat` | Новая функциональность |
| `fix` | Исправление бага |
| `chore` | Инфраструктура, CI/CD, зависимости |
| `docs` | Документация |
| `test` | Добавление или исправление тестов |
| `refactor` | Рефакторинг без изменения поведения |
| `style` | Форматирование, стили (не CSS, а код-стайл) |
